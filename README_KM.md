# SH Market — Marketplace Starter

នេះជាគម្រោងចាប់ផ្តើមសម្រាប់វេបសាយ Marketplace ដែលមានអ្នកលក់ច្រើននាក់, ការកត់ត្រាការកុម្ម៉ង់, ការគណនាកម្រៃជើងសារ និង Telegram notification។

## ត្រូវមាន
- Node.js 20 ឬថ្មីជាងនេះ
- Telegram Bot Token (បង្កើតតាម @BotFather)

## របៀបដំណើរការលើកុំព្យូទ័រ
1. ដំឡើង Node.js ពី https://nodejs.org/
2. បើក Terminal នៅក្នុងថតគម្រោង ហើយរត់ `npm install`
3. ចម្លង `.env.example` ទៅជា `.env`
4. បំពេញ `SITE_NAME`, `COMMISSION_PERCENT`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_ADMIN_CHAT_ID`
5. រត់ `npm start`
6. បើក http://localhost:3000

## Telegram
- `TELEGRAM_BOT_TOKEN`: Token ដែលទទួលបានពី @BotFather។ កុំបង្ហោះ Token ជាសាធារណៈ។
- `TELEGRAM_ADMIN_CHAT_ID`: Chat ID របស់ Admin ដែលទទួលការជូនដំណឹង។ Admin ត្រូវចាប់ផ្តើម chat ជាមួយ Bot ជាមុន។
- `/start`: សារស្វាគមន៍
- `/orders`: បង្ហាញការកុម្ម៉ង់ថ្មីៗ 10 ដំបូង

## គណនីអ្នកលក់, ការដាក់ទំនិញ និងការវាយតម្លៃ
- អ្នកលក់ត្រូវបង្កើតគណនី ឬចូលគណនីនៅផ្នែក Chat មុននឹងដាក់ទំនិញ។ ឈ្មោះគណនីនឹងត្រូវប្រើជាឈ្មោះអ្នកលក់ ហើយ Server ទទួលយកការដាក់ទំនិញតែពេលមាន token ចូលគណនីត្រឹមត្រូវ។
- ទំនិញបង្ហាញតម្លៃ USD, អ្នកលក់, ពិន្ទុមធ្យម និងចំនួនការវាយតម្លៃ។
- អ្នកទិញត្រូវចូលគណនីដដែល និងមានការកុម្ម៉ង់ដែលបានកត់ត្រា មុនវាយតម្លៃ។ ការកុម្ម៉ង់មួយអាចប្រើសម្រាប់ការវាយតម្លៃមួយប៉ុណ្ណោះ។ អ្នកលក់មិនអាចវាយតម្លៃទំនិញខ្លួនឯងបានទេ។
- Bot ក្នុងវេបសាយណែនាំរបៀបបង្កើតគណនី ដាក់ទំនិញ និងពិនិត្យការវាយតម្លៃ។ Telegram Bot មាន `/sell`, `/products`, `/help`; `/orders` ត្រូវបានកំណត់សម្រាប់ Telegram Admin Chat ID ដែលកំណត់ក្នុង `.env` ប៉ុណ្ណោះ។
- ការវាយតម្លៃជួយសម្រេចចិត្ត ប៉ុន្តែមិនធានាគុណភាពទំនិញទាំងស្រុងទេ។ ត្រូវពិនិត្យព័ត៌មានអ្នកលក់ និងគោលការណ៍ប្ដូរ/សងប្រាក់ដោយខ្លួនឯង។

## សំខាន់មុនដាក់ឱ្យប្រើជាសាធារណៈ
នេះជាគំរូ MVP សម្រាប់សាកល្បង មិនទាន់រួចរាល់សម្រាប់ប្រើប្រាស់ពាណិជ្ជកម្មពិតទេ។ មុនបើកឱ្យសាធារណៈ ត្រូវបន្ថែម៖
- Admin authentication និងសិទ្ធិអ្នកប្រើប្រាស់; ការពារផ្លូវ `/api/admin/summary`
- ការអនុម័តអ្នកលក់ និងទំនិញ, rate limiting, validation, HTTPS និង backup
- ស្ថានភាព order (pending/paid/completed/refunded) និងគោលការណ៍គណនាកម្រៃជើងសារ
- ប្រព័ន្ធបង់ប្រាក់/ទូទាត់ប្រាក់ទៅអ្នកលក់ និងការផ្ទៀងផ្ទាត់ការទូទាត់ពីអ្នកផ្តល់សេវាផ្លូវការ
- ការបង្ហោះរូបភាពដោយសុវត្ថិភាព និងគោលការណ៍ឯកជនភាព

ការកុម្ម៉ង់ក្នុងកំណែនេះគ្រាន់តែកត់ត្រាទិន្នន័យប៉ុណ្ណោះ មិនទទួលប្រាក់ពិតទេ។ កុំរក្សា ឬស្នើឱ្យអតិថិជនផ្ញើព័ត៌មានកាតធនាគារ ឬលេខសម្ងាត់តាម Telegram។


## Bot ជំនួយក្នុងវេបសាយ
មានប៊ូតុង «ជំនួយអ្នកលក់» នៅជ្រុងខាងក្រោមនៃទំព័រ។ Bot កំណែនេះឆ្លើយតាមពាក្យគន្លឹះសម្រាប់ការដាក់ទំនិញ ការកុម្ម៉ង់ កម្រៃជើងសារ និង Telegram។ វាមិនទាន់ប្រើ AI ឬចូលមើលទិន្នន័យឯកជនរបស់អ្នកលក់ទេ។ មុនប្រើពិត ត្រូវបន្ថែមប្រព័ន្ធចូលគណនី និងសិទ្ធិអ្នកប្រើប្រាស់។


## ឆាតឯកជនរវាងអ្នកទិញ និងអ្នកលក់
ទំព័រដើមមានផ្នែកណែនាំមុខងារ Chat ហើយ Database មាន schema សម្រាប់ `chat_threads` និង `chat_messages`។ ដើម្បីការពារឯកជនភាព ខ្ញុំមិនបានបើក API ឱ្យអាន/សរសេរសារដោយសេរីទេ ព្រោះកំណែនេះមិនទាន់មានប្រព័ន្ធគណនី និងការផ្ទៀងផ្ទាត់អ្នកប្រើប្រាស់។

មុនអនុវត្ត chat ពិត ត្រូវបន្ថែម៖
1. គណនីអ្នកទិញ និងអ្នកលក់ដែលមាន user ID ផ្ទាល់ខ្លួន, password hashing និង session សុវត្ថិភាព។
2. រាល់ការអាន/ផ្ញើសារ ត្រូវពិនិត្យនៅ Server ថាអ្នកប្រើជាសមាជិកនៃ thread នោះ។
3. HTTPS, rate limiting, ការការពារ spam, ការផ្ទៀងផ្ទាត់ទិន្នន័យ និងការគ្រប់គ្រងរបាយការណ៍/ប្លុក។
4. គោលការណ៍ឯកជនភាព ការរក្សាទុក/លុបទិន្នន័យ និងការកំណត់សិទ្ធិ Admin ឱ្យតិចបំផុត។
5. កុំដាក់សារឯកជន ឬព័ត៌មានផ្ទាល់ខ្លួននៅក្នុង public product pages ឬ Telegram group។

ចំណាំ៖ Database schema និង UI នេះមិនមានន័យថាមុខងារ chat ឯកជនពិតបានរួចរាល់ទេ។ កុំប្រើសម្រាប់សារពិតរហូតដល់ការផ្ទៀងផ្ទាត់អ្នកប្រើប្រាស់ និងការត្រួតពិនិត្យសិទ្ធិបានសាកល្បងរួច។

## មុខងារ Chat និងផ្ញើរូបភាព QR
- បង្កើតគណនី ឬចូលគណនីនៅផ្នែក «ជជែកផ្ទាល់ជាមួយអ្នកលក់»។ ឈ្មោះគណនីអាចប្រើអក្សរអង់គ្លេស លេខ និង `_` (3–24 តួ)។ ពាក្យសម្ងាត់ត្រូវមានយ៉ាងតិច 10 តួ។
- បញ្ចូលឈ្មោះគណនីរបស់អ្នកដែលចង់ជជែក រួចចុច «ចាប់ផ្ដើម»។ អ្នកទាំងពីរត្រូវមានគណនីក្នុងវេបសាយនេះ។
- អាចផ្ញើសារ និងរូបភាព QR ជាមួយគ្នា។ រូបភាពទទួលយក JPG, PNG, WEBP និង GIF ទំហំអតិបរមា 5MB។ ចុចលើរូបភាពក្នុងសារ ដើម្បីពង្រីកមើល។
- រូបភាពរក្សាទុកក្នុងថត `private_uploads/` ដែលមិនបង្ហោះជាឯកសារសាធារណៈ។ Server ពិនិត្យសិទ្ធិសមាជិកបន្ទប់ជជែករាល់ពេលអានសារ ឬទាញយករូបភាព។ Token ចូលគណនីផុតកំណត់ក្រោយ 7 ថ្ងៃ ហើយ browser រក្សាទុកក្នុង sessionStorage ប៉ុណ្ណោះ។
- មានការកំណត់ល្បឿនសម្រាប់ចូល/បង្កើតគណនី និងផ្ញើសារ/រូបភាព។ ប៉ុន្តែការដាក់ឱ្យប្រើពិតត្រូវដាក់ HTTPS, backup, monitoring និងការកំណត់ reverse proxy ឱ្យត្រឹមត្រូវ។
- គណនី chat បច្ចុប្បន្នមិនទាន់ភ្ជាប់ដោយស្វ័យប្រវត្តិទៅគណនីអ្នកលក់/អ្នកទិញក្នុងប្រព័ន្ធផលិតផល និងការកុម្ម៉ង់ទេ។ អ្នកត្រូវស្គាល់ឈ្មោះគណនីគ្នា។ កុំទូទាត់ប្រាក់ដោយផ្អែកលើរូប QR តែមួយ; ពិនិត្យឈ្មោះអ្នកទទួល និងចំនួនប្រាក់ជាមុន។

## ចំណាំសុវត្ថិភាព
គម្រោងនេះនៅតែជា starter/demo មិនមែនសេវាដែលបានធ្វើ security audit រួចទេ។ `/api/admin/summary` និងការបង្ហោះទំនិញនៅតែត្រូវការការពារដោយ Admin/អ្នកលក់ authentication មុនប្រើជាសាធារណៈ។ មុន deploy សូមដាក់ HTTPS និងពិនិត្យ config/backup ឱ្យបានត្រឹមត្រូវ។


## ការតាមដានការកុម្ម៉ង់, ការផ្ទៀងផ្ទាត់ទំនិញ និងរបាយការណ៍
- ការកុម្ម៉ង់មានស្ថានភាព `pending` (ទើបកុម្ម៉ង់), `shipped` (អ្នកលក់បានសម្គាល់ថាបានផ្ញើ), `delivered` (អ្នកទិញបញ្ជាក់ថាបានទទួល)។ អ្នកលក់មិនអាចបញ្ជាក់ជំនួសអ្នកទិញថាបានទទួលទំនិញទេ។
- អ្នកទិញអាចវាយតម្លៃបានតែពេលការកុម្ម៉ង់របស់ខ្លួនមានស្ថានភាព `delivered` ហើយមួយការកុម្ម៉ង់វាយតម្លៃបានម្តង។ ស្ថានភាពនេះនៅតែផ្អែកលើការបញ្ជាក់របស់អ្នកប្រើ មិនមែនភស្តុតាងដឹកជញ្ជូនពីក្រុមហ៊ុនដឹកជញ្ជូនទេ។
- ទំនិញបង្ហាញស្ថានភាពផ្ទៀងផ្ទាត់ Admin: `pending`, `verified`, ឬ `rejected`។ ស្លាក verified មានន័យថា Admin បានពិនិត្យតាមដំណើរការរបស់វេបសាយ មិនមែនការធានាគុណភាពដោយឯករាជ្យទេ។
